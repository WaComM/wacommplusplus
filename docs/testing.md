# Testing

Run the dependency-light numerical suite with the commands in [build.md](build.md). It covers interpolation bounds, vertical storage mapping, physical-time weights, shortened forward/backward steps, irregular-time forward/backward restart clipping at an exact boundary, reflection, lossless worker partitioning, and deterministic counter-key random values. Application tests add exact integration of time-linear velocity including a shortened final step and an emission inside the interval, a deterministic forward/backward round trip, deterministic forward/backward continuation from a checkpoint inside a forcing interval, seeded stochastic repeatability, exact seeded continuation at a substep boundary, OpenMP thread-scheduling independence, concentration-count preservation under OpenMP contention, configuration round-trip and validation, versioned restart metadata, explicit particle-time slicing, 64-bit identities above `2^53`, and runtime-generated ROMS, native WACOMM, NEMO, and HYCOM fixtures. Those fixtures cover staggered ROMS U/V normalization, native-format round trips, aliases, dimensions, masks, vertical orientation, normalized velocity, longitude conversion, missing W/AKT fallbacks, chronological time rejection, and cross-file boundary-record assembly for every adapter family.

Application and backend validation additionally requires NetCDF fixtures and the relevant OpenMP, MPI, or CUDA runtime. Compare particle count, identity, position, health, and age with declared absolute and relative tolerances. Platform CI is build evidence, not proof of scientific equivalence.

When configured with `USE_MPI=ON`, CTest launches a three-rank decomposition test over eleven particles. It uses the same committed MPI datatype as the application, performs the seeded stochastic particle update after a non-uniform scatter, gathers the state, and compares identity, position, health, age, and emission time exactly with serial execution.

Test targets explicitly undefine `NDEBUG`, including in Release configurations, because the regression executables use C assertions as their failure mechanism. A Release CI pass therefore executes the numerical and metadata checks rather than only launching empty test bodies.

`.github/workflows/ci.yml` runs portable platform checks plus serial, OpenMP, and MPI Ubuntu application builds. Its exact Rocky Linux 8.9 job also builds and tests the complete serial application, installs it, prints its dynamic dependencies, and fails on unresolved libraries. `.github/workflows/hpc.yml` provides scheduled/manual CUDA compilation and a QEMU riscv64 test. The CUDA kernel follows the CPU physical-time interval, interpolation, direction, closure, grid-metric, vertical-stride, and counter-key stochastic rules; compilation does not replace numerical comparison on a GPU runner. Tagged releases run the full serial application tests, installation, and runtime-link smoke check before creating a deterministic source archive and SHA-256 checksum.

All workflows declare the minimum repository permission they require, bound job duration, and cancel obsolete CI/HPC runs for the same ref. Container package installation is noninteractive. The CUDA workflow is compile-and-CPU-test validation and does not claim GPU numerical equivalence; a GPU runner and backend-equivalence fixture remain required before a release can claim measured CUDA equivalence.
