# Testing

Run the dependency-light numerical suite with the commands in [build.md](build.md). It covers interpolation bounds, vertical storage mapping, physical-time weights, shortened forward/backward steps, irregular-time forward/backward restart clipping at an exact boundary, reflection, lossless worker partitioning, and deterministic counter-key random values. Application tests add exact integration of time-linear velocity including a shortened final step and an emission inside the interval, a deterministic forward/backward round trip, deterministic forward/backward continuation from a checkpoint inside a forcing interval, seeded stochastic repeatability, exact seeded continuation at a substep boundary, OpenMP thread-scheduling independence, concentration-count preservation under OpenMP contention, configuration round-trip and validation, versioned restart metadata, explicit particle-time slicing, 64-bit identities above `2^53`, and runtime-generated ROMS, native WACOMM, NEMO, HYCOM, WRF, and WW3 fixtures. Every ocean-adapter fixture also compares continuous and checkpoint-split deterministic integration in both directions. The environmental fixtures verify WRF grid-to-Earth wind rotation, WW3 aliases and longitude normalization, factory rejection, and dynamic wind/Stokes forward-backward composition. The fixtures collectively cover dimensions, masks, vertical orientation, normalized velocity, chronological time rejection, and cross-file boundary-record assembly.

Application and backend validation additionally requires NetCDF fixtures and the relevant OpenMP, MPI, or CUDA runtime. Compare particle count, identity, position, health, and age with declared absolute and relative tolerances. Platform CI is build evidence, not proof of scientific equivalence.

When configured with `USE_MPI=ON`, CTest launches a two-rank decomposition test over eleven particles. It uses the same committed MPI datatype as the application, performs the seeded stochastic particle update after a non-uniform scatter, gathers the state, and compares identity, position, health, age, and emission time exactly with serial execution. Two ranks fit the minimum GitHub-hosted runner allocation without implementation-specific oversubscription flags, while the odd particle count still exercises a remainder on rank zero.

Test targets explicitly undefine `NDEBUG`, including in Release configurations, because the regression executables use C assertions as their failure mechanism. A Release CI pass therefore executes the numerical and metadata checks rather than only launching empty test bodies.

When Python 3 is available, CTest also creates a temporary reproducibility manifest and verifies ocean, weather, wave, and output SHA-256 values, selected CMake options, declared tolerances, and schema version. Python is optional and is not required to configure or build the portable C++17 numerical core.

When the optional Python `netCDF4` package is available, `trajectory_diagnostics` creates deliberately unordered synthetic snapshots, filters an inactive member, joins stable identities, preserves embedded revision provenance, handles an antimeridian-crossing ensemble, verifies physical-time ordering and nonzero spread, and inspects required SVG metadata. CTest reports a skip when that optional analysis dependency is absent; this does not affect the C++ model build.

The environmental-adapter fixture additionally checks WRF timestamp parsing and grid-vector rotation, CF time conversion from minutes to the WaComM epoch, CF-oriented Stokes aliases, longitude normalization, and rejection of unsupported velocity units. The documentation-visual test parses every repository SVG, requires accessible title and description elements, verifies that each asset is referenced by a document, and checks that the OpenDrift comparison contains a displayed governing equation and explicitly identifies its conceptual map as non-georeferenced. This is structural verification; scientific review remains responsible for the truth and interpretability of each visual.

The dependency-light `environmental_regridding` test verifies exact preservation of a constant field, affine-field interpolation on a refined target grid, increasing and decreasing axes, antimeridian crossing, inverse mapping within a warped curvilinear cell, indexed lookup across a 600-cell analytically representable warped grid, and rejection of extrapolation, a non-rectilinear source passed to the rectilinear operator, and folded geometry. Application adapter tests additionally exercise regridding through the public wave-adapter interface. These are verification tests of the implemented operator, not evidence that bilinear interpolation is scientifically suitable for every forcing product or a performance guarantee for all grid geometries.

With `USE_PROJ=ON`, tests check EPSG:4326-to-EPSG:3857 control coordinates, affine rectilinear and warped curvilinear fields, metric `x/y` parsing for WRF and WW3, indexed Cartesian location, and preservation of Earth-relative components. The default build verifies fail-fast rejection. These comparisons verify implementation behavior, not every CRS or datum resource.

`.github/workflows/ci.yml` runs portable platform checks plus complete serial application builds on Ubuntu, Rocky Linux 8.9, macOS Intel, macOS Apple Silicon, Windows/MSVC with vcpkg, and a Raspberry Pi OS ARM64 proxy. Ubuntu additionally validates OpenMP, MPI, and combined MPI/OpenMP execution. `.github/workflows/hpc.yml` compiles the combined MPI/OpenMP/CUDA hierarchy, tests OpenACC, and builds the complete application under Debian Trixie riscv64 through QEMU. The CUDA kernel follows the CPU physical-time interval, interpolation, direction, closure, grid-metric, vertical-stride, and counter-key stochastic rules. `cuda_particle_parity` compares deterministic and seeded-stochastic CPU/GPU state when a device is present and reports a CTest skip when it is not. `.github/workflows/gpu.yml` executes that test on a manually selected self-hosted GPU runner, while `.github/workflows/flexmpi.yml` validates a self-hosted FlexMPI installation. Tagged releases gate source publication on serial, OpenACC, and CUDA compile/CPU-test validation before creating a deterministic source archive and SHA-256 checksum.

All workflows declare the minimum repository permission they require, bound job duration, and cancel obsolete CI/HPC runs for the same ref. Container package installation is noninteractive. A successful CUDA container build with a skipped parity test remains compile-only evidence; a successful self-hosted GPU workflow is required before a release can claim measured CUDA equivalence. FlexMPI claims likewise require the dedicated workflow on an installation providing `empi.h`, the EMPI library, and its configured MPI runtime.

Surface-drift validation adds zero-wind finiteness, pure downwind direction, equal-and-opposite left/right crosswind motion, catalog identity, configuration validation, deterministic forward/backward current-plus-leeway reversal, version 3 restart persistence, MPI metadata preservation, and deterministic CPU/CUDA leeway parity. Coefficient-ensemble tests additionally verify the residual equation, same-seed/same-identity repeatability, distinct members, forward/backward reversal for one member, configuration persistence, and CPU/CUDA parity. The CUDA parity assertion executes only on a CUDA-capable host; compilation alone is not parity evidence.
