# Testing

Run the dependency-light numerical suite with the commands in [build.md](build.md). It covers interpolation bounds, vertical storage mapping, physical-time weights, shortened forward/backward steps, irregular-time forward/backward restart clipping at an exact boundary, reflection, lossless worker partitioning, and deterministic counter-key random values. Application tests add exact integration of time-linear velocity including a shortened final step and an emission inside the interval, a deterministic forward/backward round trip, deterministic forward/backward continuation from a checkpoint inside a forcing interval, seeded stochastic repeatability, exact seeded continuation at a substep boundary, OpenMP thread-scheduling independence, concentration-count preservation under OpenMP contention, configuration round-trip and validation, versioned restart metadata, explicit particle-time slicing, 64-bit identities above `2^53`, and runtime-generated ROMS, native WACOMM, NEMO, and HYCOM fixtures. Every adapter fixture also compares continuous and checkpoint-split deterministic integration in both directions. The fixtures cover staggered ROMS U/V normalization, native-format round trips, aliases, dimensions, masks, vertical orientation, normalized velocity, longitude conversion, missing W/AKT fallbacks, chronological time rejection, and cross-file boundary-record assembly for every adapter family.

Application and backend validation additionally requires NetCDF fixtures and the relevant OpenMP, MPI, or CUDA runtime. Compare particle count, identity, position, health, and age with declared absolute and relative tolerances. Platform CI is build evidence, not proof of scientific equivalence.

When configured with `USE_MPI=ON`, CTest launches a two-rank decomposition test over eleven particles. It uses the same committed MPI datatype as the application, performs the seeded stochastic particle update after a non-uniform scatter, gathers the state, and compares identity, position, health, age, and emission time exactly with serial execution. Two ranks fit the minimum GitHub-hosted runner allocation without implementation-specific oversubscription flags, while the odd particle count still exercises a remainder on rank zero.

Test targets explicitly undefine `NDEBUG`, including in Release configurations, because the regression executables use C assertions as their failure mechanism. A Release CI pass therefore executes the numerical and metadata checks rather than only launching empty test bodies.

When Python 3 is available, CTest also creates a temporary reproducibility manifest and verifies forcing and output SHA-256 values, selected CMake options, declared tolerances, and schema version. Python is optional and is not required to configure or build the portable C++17 numerical core.

`.github/workflows/ci.yml` runs portable platform checks plus complete serial application builds on Ubuntu, Rocky Linux 8.9, macOS Intel, macOS Apple Silicon, Windows/MSVC with vcpkg, and a Raspberry Pi OS ARM64 proxy. Ubuntu additionally validates OpenMP, MPI, and combined MPI/OpenMP execution. `.github/workflows/hpc.yml` compiles the combined MPI/OpenMP/CUDA hierarchy, tests OpenACC, and builds the complete application under Debian Trixie riscv64 through QEMU. The CUDA kernel follows the CPU physical-time interval, interpolation, direction, closure, grid-metric, vertical-stride, and counter-key stochastic rules. `cuda_particle_parity` compares deterministic and seeded-stochastic CPU/GPU state when a device is present and reports a CTest skip when it is not. `.github/workflows/gpu.yml` executes that test on a manually selected self-hosted GPU runner, while `.github/workflows/flexmpi.yml` validates a self-hosted FlexMPI installation. Tagged releases gate source publication on serial, OpenACC, and CUDA compile/CPU-test validation before creating a deterministic source archive and SHA-256 checksum.

All workflows declare the minimum repository permission they require, bound job duration, and cancel obsolete CI/HPC runs for the same ref. Container package installation is noninteractive. A successful CUDA container build with a skipped parity test remains compile-only evidence; a successful self-hosted GPU workflow is required before a release can claim measured CUDA equivalence. FlexMPI claims likewise require the dedicated workflow on an installation providing `empi.h`, the EMPI library, and its configured MPI runtime.
