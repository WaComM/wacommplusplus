# Restart

NetCDF restart variables use dimensions `[particles, particle_time]`; the loader reads an explicit single time slice and preserves `ncUint64` identity without conversion through `double`. Version 3 adds per-particle `object_type` and `drift_side` to the version 2 state and records `checkpoint_time`, `tracking_direction`, `random_seed`, `ocean_model`, configured Git revision, compiler, CMake backend options, configuration path, and the complete resolved JSON configuration. Object IDs 0--5 retain their original catalog meanings; broader entries use subsequent IDs, so an earlier version-3 restart remains semantically stable. The loader rejects unsupported versions and configured direction, seed, or ocean-model mismatches. Restarts also record `wacomm_random_key_scheme`; a different recorded scheme is rejected because continuation would switch to another random realization. Restarts written before the attribute existed carry no scheme and are accepted, but stochastic continuation from them is not equivalent to an uninterrupted run under the current scheme. Version 2 remains readable for passive transport but is rejected for leeway runs because deterministic continuation requires object state. Text restart files append object type and side while retaining historical passive records. They are written with `max_digits10` decimal digits and read with exact 64-bit identity parsing, so a text round trip reproduces positions, age, health, and physical time bit for bit. Before this fix, six-significant-digit output could move a physical time near $1.7\times10^9$ s by up to 5000 s. GeoJSON histories are not restart files: they leave out inactive and out-of-domain particles and the restart metadata, so loading one fails rather than starting from an empty particle set. The [application verification](application-verification.md) seeds a deterministic backward run from forward text endpoints and requires a round trip below 1 mm.

An initial restart can also be generated from GeoJSON polygon release areas by `createRestartFileFromJson` ([polygon releases](model.md#polygon-releases)). It writes version 3 through the same writer, with `checkpoint_time` set to the release time, and adds `wacomm_polygon_release_file`, `wacomm_polygon_release_sampler`, and `wacomm_polygon_release_time`. The tool reads the file back with this loader and fails unless every particle is reproduced exactly. The earlier Python generator wrote unversioned files with nearest-node non-negative integer indices and 32-bit float identities, sampled with an unseeded generator, and has been removed.

For reproducible continuation, archive the restart checksum, forcing manifest, configuration, seed, direction, ocean model, and physical checkpoint time. Legacy restart files lack enforced direction metadata and must be verified externally.

Versioned continuation clips each forcing interval by physical time. Forward intervals ending at or before the checkpoint and backward intervals beginning at or after it are skipped before source emission, particle distribution, concentration evaluation, or output work. Uniform-rate releases are pre-registered for the complete forcing interval and remain inactive until their stored physical release times. Consequently, a checkpoint inside an interval already contains its later inactive releases; continuation suppresses rescheduling that partial interval and resumes scheduling at the next interval. Boundary checkpoints schedule the new interval once. The dependency-light tests cover forward and backward clipping plus rate-schedule decomposition.

Exact stochastic continuation requires the checkpoint to coincide with a completed integration substep and the forcing bracket, configured `dti`, `physics.integrator`, seed, and particle identities to remain unchanged. The random key uses the absolute forcing-interval time and substep number, so a restart at such a boundary reproduces the uninterrupted stochastic state. A checkpoint inside a stochastic substep changes the step partition and is not claimed to be bitwise equivalent.

Leeway-coefficient ensemble residuals are regenerated from the archived random seed and stored particle identity rather than added to the restart schema. Initial assignment and later jibing share the persisted resolved `drift_side`; loading never resamples it. Jibing keys use the physical forcing interval and absolute substep, so continuation is exact at a completed substep boundary when seed, identity, object type, `dti`, hourly probability, side, and resolved configuration are unchanged. A checkpoint inside a jibing substep changes event partitioning and has no bitwise-equivalence claim.

Regional observational calibration adds no restart field. Its wind-error tuple is selected from the restarted physical position and the archived resolved configuration at every substep. Completed-substep restart equivalence therefore requires the identical ordered region definitions and provenance-bearing configuration. Forward and backward selection use the same geographic test; stochastic backward trajectories remain candidate origins rather than inverses.
