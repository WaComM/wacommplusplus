# Architecture

`Config` parses runtime policy and resolves each environmental reference as a local path or an explicit HTTP, HTTPS, or DAP4 URI. `WacommPlusPlus` traverses forcing windows in physical direction and selects explicit ocean, weather, and wave adapters. A bounded cache holds the current and adjacent normalized windows; the adjacent object becomes the next current object, after which the previous window is released. This is application-level lazy access: NetCDF controls protocol requests and its chunk cache, while every selected adapter still performs complete validation and normalization before exposing fields to physics. `OceanModelAdapter`, `WeatherModelAdapter`, and `WaveModelAdapter` normalize product-specific coordinates and fields without changing temporal direction. `Wacomm` coordinates forcing records, sources, decomposition, particle execution, concentration, and output. `Particle` contains the reference CPU numerical update. The CUDA kernel implements the same physical-time interpolation, shortened steps, direction policy, closures, grid metrics, vertical indexing, environmental-vector composition, and counter-key stochastic specification; backend code changes scheduling and memory placement, not the physical model. Normalized WRF wind and WW3 Stokes arrays are copied with each forcing window and sampled in the kernel; product parsing, rotation, regridding, and metadata validation remain host-side adapter responsibilities.

The execution hierarchy is forcing progression, MPI/FlexMPI decomposition, OpenMP particle parallelism, and optional CUDA execution. Backend work distribution may differ, but equations and closures may not.

Forcing progression keeps the current normalized adapter plus one adjacent adapter long enough to copy a single boundary record. Forward traversal appends the next file's first record; backward traversal prepends the older file's last record. Compatibility checks cover dimensions, sigma coordinates, longitude, latitude, bathymetry, and mask before any dynamic array is indexed.

When explicitly configured, environmental regridding occurs after adjacent-file boundary assembly and before construction of `Wacomm`. Product-specific adapters have therefore already normalized time, units, longitude convention, and vector basis. The shared geographic bilinear operator changes only the horizontal representation; `Wacomm` subsequently applies the same time/grid compatibility checks as for an exact-match run. No regridding branch exists inside `Particle` or any execution backend.

Curvilinear preprocessing builds a deterministic uniform spatial index over locally unwrapped cell bounding boxes. Candidate lists retain source row-major order. A target query narrows the candidate set before the original inverse-bilinear Newton solve, residual criterion, and Jacobian-sign fold test; consequently the index cannot select different interpolation equations or backend physics.

Projected preprocessing is an optional adapter-layer operation. PROJ transforms EPSG:4326 ocean targets into an explicitly declared source CRS, while fields remain in their normalized Earth-relative vector basis. Transformed coordinates enter the rectilinear weights or the same indexed inverse-bilinear geometry with cyclic handling disabled. Neither the solver nor an execution backend contains CRS logic.

Conservative remapping is a separate shared preprocessing primitive for geographic cell averages. Rectilinear spherical rectangles or convex curvilinear polygons in local $(\lambda,\sin\phi)$ coordinates define overlap moments before solver/backend execution. Fractional active area scales extensive content, while the optional second-order mode reconstructs a limited centroid-relative linear field. It is not exposed as a weather or wave velocity option because conservation semantics depend on the sampled quantity, staggering, and vector basis.

Surface drift follows the same hierarchy. `DriftObjectType` and resolved `DriftSide` are fixed-width particle state; `DriftObjectCatalog` is the single source for restart-stable identities, provenance keys, descriptions, and side-specific coefficients; and the allocation-free leeway, correlation, and hazard functions are shared by CPU and CUDA code. `DriftProcessCatalog` describes the existing operators and their configuration contracts but is not a second dispatch layer: the solver remains the only implementation of each equation. Fixed coefficient residuals, substep wind errors, initial side selection, diffusion, and jibing use disjoint counter-key coordinates. Wind errors are added in the Earth-relative basis before leeway evaluation; side selection occurs during source emission; jibing occurs after displacement using physical step duration; restart stores the resolved side while stateless keys reproduce the other terms. `Config` selects the model and environmental provider before integration. Passive runs follow a configuration-level fast path and do not incur object uncertainty.

Observational-calibration regions are validated into a bounded, fixed-width configuration array so the serial, OpenMP, MPI, and CUDA paths consume identical data. The shared selector converts the already-normalized particle longitude and latitude from radians to EPSG:4326 degrees and chooses the sole containing rectangle. Regions cannot overlap or share a boundary. Selection only substitutes the wind-error parameter tuple; adapters, interpolation, random coordinates, and solver direction remain unchanged. Human-readable estimator and dataset provenance stays in the resolved JSON embedded with outputs, while the numeric region table is copied to accelerator memory.

The wind-error operator is a stateless counter-key field shared by CPU and CUDA. Positive spatial and temporal support scales replace particle and substep coordinates with Earth-relative block-cell and absolute physical-time-bin coordinates; the component Cholesky transform is applied after sampling. No backend stores or evolves a separate forcing-error state.
